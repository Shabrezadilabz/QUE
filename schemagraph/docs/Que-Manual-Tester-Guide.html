We did not open a cloud Postgres (RDS / Neon / Supabase) account for this local test. Credentials come from the Docker container that already runs Que’s metadata DB.

4.1 Commands — create Postgres “account” (Docker) if missing

# Check
docker ps -a --filter name=stitch-pg

# Start existing
docker start stitch-pg

# FIRST TIME ONLY — creates user stitch / password stitch / db stitch
docker run -d --name stitch-pg `
  -e POSTGRES_USER=stitch `
  -e POSTGRES_PASSWORD=stitch `
  -e POSTGRES_DB=stitch `
  -p 5432:5432 `
  pgvector/pgvector:pg16

# Wait until ready
docker exec stitch-pg pg_isready -U stitch -d stitch
That single Docker user is both the Que metadata login (DATABASE_URL) and the customer-source login. Only the database name differs (stitch vs customer_demo).

8. Step 6 — Workspace alignment & joins (HITL)

Do this after all connectors sync

Goal: see tables from Postgres + Mongo + Databricks + Excel/CSV on one canvas, review suggested joins on shared keys (email, customer_id / pg_customer_id), then Promote good joins and Reject noise. Que never auto-accepts joins.

8.1 Preconditions

  • All Step 2–5 connectors created and Synced
  • You are signed in as workspace owner
  • UI http://localhost:5174 · API :8787 healthy

8.2 Open Workspace & check alignment

  1. Nav → Workspace
  2. Confirm table nodes from multiple sources (PG customers/orders, Mongo events/profiles, DBX dim_customer/fact_orders, Excel/CSV sheets)
  3. Drag tables to arrange; reload page — layout should persist
  4. Optional: run stitch / join-inference from UI if a “Suggest joins” / Stitch session control is shown
Expected join signals: same emails (ada@example.com, user{N}@example.com) and customer_id / pg_customer_id across PG ↔ Mongo ↔ Excel ↔ Databricks samples.

8.3 HITL — Promote & Reject

  1. Click a suggested relationship edge (dashed / “suggested” styling)
  2. Read the evidence (column names, samples)
  3. Click Promote on at least one good cross-source join (e.g. PG customers.email ↔ Mongo profiles.email)
  4. Click Reject on at least one weak/noise suggestion
  5. Confirm promoted edges look “accepted / explicit”; rejected ones no longer drive export
#StepExpectedResult
8.1 Workspace shows multi-source tables PG + Mongo + DBX + files visible ☐ PASS ☐ FAIL
8.2 Suggested joins appear on shared keys At least some suggested edges ☐ PASS ☐ FAIL
8.3 Promote ≥1 join Status accepted; evidence retained ☐ PASS ☐ FAIL
8.4 Reject ≥1 join Rejected; not used for export ☐ PASS ☐ FAIL
8.5 Reload Workspace Layout + review decisions persist ☐ PASS ☐ FAIL
If no suggestions: re-Sync sources · confirm shared emails exist · try Stitch session selecting two sources · check Settings that join inference is enabled.

10. Step 8 — AI Chat → Jobs → Deploy

Final product path

Wedge path: Chat (schema-only) → draft job → notebook → Run Test / Validate → Mark Ready → Deploy / attested export. Joins you Promoted in Step 6 should be preferred; AI still does not auto-accept joins.

10.1 Chat smoke

  1. Nav → Chat
  2. Try: list tables
  3. Try: describe customers (or @customers mention)
  4. Try: ask how to join Postgres customers to Mongo events / Excel leads on email
  5. Confirm answers cite schema — not full warehouse dumps

10.2 Draft a job from Chat

  1. Ask Chat to draft a job stitching two sources (e.g. PG customers → Mongo events or Excel leads)
  2. Save / open the draft when offered
  3. Nav → Jobs · confirm the job appears in the list

10.3 Jobs notebook · Results · Deploy

  1. Open the job → tab Notebook
  2. Edit SQL / markdown cells if needed · Commit / save changes
  3. Click Run Test (dry-run) — Process/Output populate; no warehouse write
  4. Optional: run mode Validate · ≤20 against live PG (capped rows only)
  5. Open tab Results — preview samples from last run
  6. Mark job Ready when satisfied
  7. Open tab Deploy — review governance · export JSON / SQL / dbt (or dbt PR if GitHub configured)
  8. Confirm attestation / signature present on export, or a clear block reason (e.g. unreviewed joins, drift)
Job URL shape: /jobs?job={id}&tab=notebook|results|deploy
