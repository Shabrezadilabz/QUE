2. Product DNA & Offer A / B

RuleWhy it matters in production
Schema-firstConnectors introspect structure; they do not ETL your lake into Que.
Pinned samples 5–10Scrubbed, frozen until re-pin; used for join overlap ~88–95% band.
Human PromoteSuggested joins are not truth until Promote (HITL).
Attested deliveryExports / jobs carry evidence; warehouse (or managed plane) is SoR for rows.
AI denied lakeaiMayUsePinnedSamples default ON; managed row payloads denied to AI.

Offer A — Bring your warehouse

Databricks / Snowflake / Postgres stay system of record. Que proposes joins, drafts jobs, digests external run failures, exports / triggers.

When: You already have a warehouse and want control-plane HITL.

Offer B — Que managed plane

Excel/SQL teams land certified datasets in Que (quotas + retention). Certify → BI charts → embed.

When: No warehouse yet, but need attested DA path.

5. Scenario A — Offer A warehouse stitch (production day)

Goal: Two sources → trusted joins → job → attested handoff into customer warehouse; failures digested in Que.

  1. Login as owner/admin → open /product once for positioning, then /sources.
  2. Add Postgres + Excel (or Databricks/Snowflake). Click Sync schema. Confirm pins created (scrubbed samples).
  3. Go to /joins. Filter Suggested. Open a high-score edge. Review evidence + overlap.
  4. If columns wrong: edit mapping → save → Promote. Discuss in thread comments with DE/DA.
  5. /settings/ai-policy: set execution plane to customer (Offer A). Keep pinned samples ON.
  6. /jobs: create or open job from stitch / marketplace pack. Dry-run (samples). Live validate only when ready.
  7. Export / trigger warehouse job. Post status via external-status bridge (or automation).
  8. /compliance → Build digest for Offer A failure summary. Chat shows Offer A strip too.
  9. /lineage + export attestation verify at /verify for auditors/partners.
Success: Promoted joins feed job contract; warehouse remains SoR; Que holds decisions + evidence.

6. Scenario B — Offer B managed plane + certified BI

Goal: Excel/SQL team lands a certified table in Que and embeds a chart for stakeholders.

  1. Enable managed plane in /settings/ai-policy (enableManagedDataPlane).
  2. Connect Excel/CSV → sync → promote joins → job dry-run → Land to managed (from job flow).
  3. /managed: open dataset → review columns → Certify.
  4. /metrics: define COUNT(*) or SUM(amount), optional source column for lineage → Certify → Publish BI.
  5. /bi: bind certified dataset, set chart type/axes, Preview, Certify, Mint embed.
  6. Share viewer URL /embed/<token> (public, read-only). API also at GET /bi/embed/:token.
  7. Watch quotas/retention on managed plane; purge expired from ops/compliance path as needed.
AI still cannot pull managed row payloads. Embeds are for humans/stakeholders.

7. Scenario C — Team Cursor loop (daily DE/DA)

  1. Admin seeds org /rules (join conventions, naming, PII).
  2. DE opens /agent or /chat with @tables → draft transform / job.
  3. Transform lands in /transforms and/or /proposals as open diff.
  4. Peer reviews unified diff on /proposals → Approve / Reject.
  5. On Promote, rules can learn patterns. Comments/threads on /joins capture debate.
  6. /eval: configure golden pairs JSON → enable schedule → Run now; watch recall.
  7. /marketplace: install industry pack to bootstrap a job when starting a domain.

8. Every page — detailed production use

8.0 Public pages (no login)

/login — Login

What: Email/password and optional SSO continue.

Do: Sign in → lands on Workspace. Use SSO when org enforces it.

Scenario: New hire invited → accepts invite → login → switches workspace if multi-tenant.

/sales — Public sales

Honest positioning for prospects (Offer A/B). CTA to login / status. Not a full marketing site.

/status — Public status

Ops transparency: API ok, DB latency, inventory counts, region. Share with clients during incidents.

/verify — Attestation verify

Paste/export fingerprint or token to verify attested artifacts independently of login.

/embed/:token — Certified BI viewer

Read-only chart for stakeholders. Token minted only after chart certify. Revoke from BI admin actions.

8.1 /workspace — Schema canvas

Purpose

Visual system of record for schema truth: tables as nodes, relationships as edges.

What to do

  • Pan/zoom canvas; drag tables (members+); expand columns.
  • Select table → right inspector: schema, samples (capped), add to job.
  • Filter by source; use TopBar confidence / join filters when available.
  • Viewers: read-only (no drag persist).

Production scenario

After sync, DE opens Workspace to sanity-check that Excel + Postgres tables both appear, then jumps to Joins for HITL.

8.2 /sources — Connectors & sync

Purpose

Register connectors and sync schema + pinned samples.

Connectors (typical)

PostgreSQL, Excel/CSV, MongoDB, Databricks, Snowflake, BigQuery, Salesforce (fixture and/or live).

How to use

  1. Add source → pick connector → fill form (or fixtures path for demos).
  2. Sync schema — retries/checkpoints apply automatically.
  3. Set sync schedule (hourly/daily/off) for continuous introspect.
  4. On error: check health kind (auth vs transient); fix secrets; re-sync.

Scenario

Ops schedules nightly sync for Snowflake. Auth failure stops tight loops; transient errors retry with backoff.

SLA view: API /connector-reliability also surfaces on Compliance.

8.3 /joins — Join Review (HITL)

Purpose

The trust gate. Suggested joins become production truth only after Promote.

Controls

  • Filters: suggested / accepted / rejected / all
  • Evidence: name/type, uniqueness proxy, pinned overlap score
  • Edit columns / direction → save → Promote or Reject
  • Team discussion: comment + Reply threads
  • Re-run join inference / mapping assist / golden eval hooks as available

Scenario

DA believes customer_id ↔ cust_id. Overlap 91%. DE edits left/right columns, threads “confirmed in CRM”, Promotes. Proposal/diff may also appear for audit.

Never claim 100% join accuracy. Band ~88–95% on easy keys with pins.

8.4 /chat — AI Chat

Purpose

Schema-only assistant: design questions, SQL drafts, job drafts. Uses schema packs + optional pinned samples.

How to use

  • @mention tables; slash skills; sidebar focus tables
  • Ask for join rationale, notebook steps, validation checks
  • Save job draft when offered (members+)
  • Offer A strip: refresh warehouse digest without leaving chat

Scenario

“Draft a reconciliation job using promoted joins between ledger and bank_feed” → review SQL → save job → open Jobs.

8.5 /agent — Stitch Agent

Purpose

Multi-step agent sessions (checkpoints) for stitch goals, including draft_transform.

How to use

  1. Create session with a clear goal (“transform events to weekly active accounts”).
  2. Advance checkpoints; when joins needed, Promote in Joins then continue.
  3. Resulting transform/proposal appears in Transforms / Proposals for HITL.

8.6 /jobs — Notebook → ship

Purpose

Production stitch jobs: markdown + SQL notebook, freeze contract, dry-run, live validate, export, schedule, materialize.

Tabs / actions (typical)

  • Notebook editor (SQL cells)
  • Dry-run (capped samples) vs live (bounded rows)
  • Export JSON / SQL / dbt / dbt PR (gates: promoted joins, drift)
  • Schedules + private runner / orchestrator hooks
  • Templates panel; land to managed when Offer B
  • Contract tests run history

Scenario

After Promote, open job → dry-run → fix null keys → export dbt PR → warehouse CI runs → external status posts back → digest on Compliance.

8.7 /proposals — Approve / Diff

Purpose

PR-style inbox for joins, transforms, SQL changes.

How to use

  • Toggle Unified vs side-by-side
  • Approve / Reject (members+)
  • Link to Agent for drafting context

Scenario

Junior DA drafts transform; senior DE reviews unified diff; Approve applies workspace truth.

8.8 /transforms — NL → SQL HITL

Purpose

Natural-language transform drafts with review states (proposed → approved/rejected/applied).

Scenario

“Weekly active accounts from events” → draft SQL → review → approve → attach/open job.

8.9 /rules — Org memory

Purpose

Cursor-like rules injected into AI + team conventions. Can learn from Promote.

How to use

  • Create join / naming / PII rules; enable/disable
  • After Promote, confirm learned rule suggestions

Scenario

Rule: “Never join on email alone for finance.” Chat/agent respects it in drafts.

8.10 /metrics — Semantic layer

Purpose

Certified metrics on managed datasets; lineage-to-metric graph.

How to use

  1. Create metric name + expression (COUNT(*), SUM(amount))
  2. Bind certified managed dataset; optional source column
  3. Preview → Certify → Publish BI
  4. Inspect metric lineage edges on the page

8.11 /bi — Certified BI

Purpose

Lightweight charts (table/bar/kpi/pie) on certified managed data; embed tokens.

How to use

  1. Create chart → bind certified dataset → set type/x/y
  2. Preview → Certify → Mint embed (admin)
  3. Copy viewer URL /embed/… and API GET URL
Not a Tableau replacement — stakeholder embeds with certification gate.

8.12 /managed — Offer B datasets

Purpose

Host job outputs with quotas/retention when no warehouse SoR.

How to use

  • List datasets; open rows (capped UI); certify; delete when obsolete
  • Only certified datasets feed BI / metrics publish

8.13 /marketplace — Industry packs

Purpose

Install starter job packs (retail, finance, SaaS, healthcare, logistics, marketing, HR, platform, Snowflake/dbt, Databricks gold).

How to use

  • Filter industry/tag/search → Install → opens draft job
  • Review recent installs list

Scenario

New finance domain: install Ledger reconciliation → sync real tables → remap joins → Promote → run.

8.14 /eval — Quality dashboard

Purpose

Promote rates, job success, rules coverage + scheduled golden-set eval.

How to use

  • Read KPI cards weekly in ops review
  • Admin: paste golden pairs JSON → Save & enable → Run now
  • Recall drops are audited (alerts path)
  • Quick-apply industry templates (or use Marketplace)

8.15 /lineage — Lineage lite

Purpose

Metadata lineage (not warehouse-native full column graph for every vendor).

Scenario

Before export, DA checks which tables feed the job; pairs with column-lineage API when investigating a metric.

12. Claims you can / cannot make

You can say
  • Schema-first HITL stitch control plane
  • Pinned scrubbed samples; ~88–95% band on easy keys
  • Attested exports into customer SoR
  • Evidence pack for auditor diligence
  • Offer A + Offer B dual path
Do not say
  • We replace Databricks/Snowflake
  • AI is always 100% correct / no humans
  • We are SOC 2 Type II certified (unless auditor letter exists)
  • Que is the enterprise lake for all rows
  • Certified BI is a full Tableau suite

13.8 Compliance ops drill (quarterly)

  1. Refresh SOC2 evidence pack → download markdown → attach to diligence folder.
  2. Run metadata backup → confirm checklist “backup” done.
  3. Run DR drill → confirm passed steps (backup + isolation + db ping).
  4. Build warehouse digest → file Offer A failures with owners.
  5. Confirm connector SLA counts (ok/degraded/breached).
  6. Note: this is evidence, not Type II certification.
